## Feature contract and acceptance criteria

1. **Coin economy:** Model accrual from wall time, not animation frames. The deterministic simulator must be independent of tick frequency to the nearest cent. Purchases are validated atomically; prices, earnings, satisfaction, neighbor bonuses, and staff effects shown in the interface must match actual functions. Existing source constants: base car price and income, 1.95x new-car price multiplier, 2.4x level cost multiplier, 1.27x level-income multiplier, maximum room level 12 and 25-carriage cap. Do not invent unlimited train length. Verify no negative balances, infinite-currency exploits, or silent runaway values. Provide active and casual policy evaluations at 1m, 10m, 1h, 1d, 7d, 30d. Report policy assumptions and distinguish model evidence from human playtesting.
2. **Slower carriage progression:** Define car unlocks by both stops and prior train length: sleeper/café immediate; Glasshouse (2 stops); Library (6 stops, 3 cars); Dining (14, 4); Arcade (30, 5); Workshop (65, 7); Observatory (120, 9). Show exact gating in Shop; locked items must never charge coins.
3. **World exploration:** Eight regional route chapters with sixteen named destinations and individual postcards, unlock requirements based on cumulative station arrivals, cars, and Stamp prices. Keep regional visuals attached to `activeRegion`; use atmospheric layers, not false claims of wholly unique hand-painted backgrounds. Players can revisit owned regions without paying twice; chapter selection changes subsequent destinations. Region selection persists in saves. Repeated arrivals award milestone Stamps every 18 stops; no offline station advancement.
4. **Residents and dream jobs:** Named, deterministic residents with profession/dream assignment. Hiring one of two spots per car costs coins. Any resident increases rate; dream matches provide an additional rate bonus; satisfaction also contributes to real revenue and station fares. Persist crew identity and never generate arbitrary hidden bonuses unrelated to displayed rules.
5. **Postcard Stamp utility:** Permanent Postcard Gallery, Concierge Academy, and Souvenir Counter projects with one-time validated Stamp costs. Show cost, actual effect, owned state, and availability. Stamp balance cannot go negative. Stamps remain obtainable from unique postcards, achievements, rare sightings, and station milestones.
6. **Voluntary prestige:** Allow beginning a new timetable only at 20 carriages and three owned regions. Require explicit confirmation. Reset current cash/rooms/stops, retain lifetime stops, owned regions, postcards, collectibles, cosmetics, completed Stamp projects, and Stamps. Each completed timetable earns +16% permanent income, up to ten. It is always optional; show what resets and what stays.
7. **Local saves:** Default to v4, detect and migrate v3 transparently, retain previous player assets and collections, validate all imports, write a checksum envelope and three rotating locally stored backups, offer manual export/import/recovery/reset, and cap offline accrual at eight hours. Warn about concurrent tabs: a stale tab must not silently overwrite another tab's saved progress. Be explicit that `localStorage` is scoped to browser profile and origin; it is not cloud sync, cryptographic proof, or durable against browsing-data removal. A server-based cross-device sync system would require a separate design and opt-in accounts.
8. **Art/layout:** Preserve train sprites and the painted world. Region visuals must change based on the chosen route. Maintain stable typography, deliberate spacing, labels, and 44×44 CSS-pixel primary controls at 1440×900, 820×1180, 390×844, and 320×650. Review actual rendered mobile screenshots including Shop, Journal, Region menu and active train.
9. **Security and integrity:** No untrusted script injection, network downloads, external API keys, speculative security claims, or hidden debug mutators. Validate imported JSON shape, size, version, identity arrays, value bounds, foreign object fields, and atomic transactions. Checksums detect accidents, not tampering; client-side economics cannot be authoritative. Do not pretend local save encryption or client-side cheating prevention is sufficient for multiplayer.
10. **Deployment and evidence:** Implement on a dedicated feature branch. Run `npm run verify` and browser regression, save migration/backups/reload, all new purchases, and build regeneration. Record failures with fixes. Update `README`, `docs/STATUS.md`, `docs/BALANCE.md`, and `AGENTS.md`. Open a PR and report the PR URL and actual GitHub Actions status; merge only once verified. Confirm live GitHub Pages deployment separately. Deliver a complete ZIP and a self-contained offline HTML, with verified file paths.
